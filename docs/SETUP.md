# Setup

How this profile repository is wired up and how to run it yourself.

## Prerequisites

- A GitHub repository named after your username (the profile repository).
- GitHub Actions enabled for the repository.
- Python 3.12 only if you want to run the card script locally.

## Token

The workflows read contribution data through the GraphQL API using a personal access token stored as the repository secret `PROFILE_PAT`. Create the token, then add it under *Settings > Secrets and variables > Actions*. Never commit the token.

## Workflows

| Workflow | Schedule (UTC) | Output |
| --- | --- | --- |
| `3d-contrib.yml` | 03:00 and 18:00 daily | `profile-3d-contrib/` |
| `profile-card.yml` | 03:30 and 18:30 daily | `assets/` |
| `snake.yml` | every 12 hours | `output` branch |

All three can also be started manually (`workflow_dispatch`) and run on every push to `main`.

## 3D graph colours

Colours for the 3D contribution graph live in `.github/3d-contrib-settings.json`. The `season` type takes four palettes (`contribColors1` to `contribColors4`); the first colour of each palette is the tile base for that part of the year. Edit the file, push, and the workflow regenerates `profile-3d-contrib/profile-custom.svg`.

## Running the card script locally

```bash
pip install requests
GITHUB_TOKEN=<token> USERNAME=<your-username> UTC_OFFSET=6 python .github/scripts/generate_profile_cards.py
```

The script writes the generated SVG cards into `assets/`. `UTC_OFFSET` shifts the commit-hour chart to your local time.

## Troubleshooting

- **Push rejected in a workflow:** the bot commits to `main` too. The workflows already fetch and rebase before retrying.
- **Cards look stale:** images are cached by GitHub; wait a few minutes or hard refresh.
- **A card is empty:** check that `PROFILE_PAT` exists and has not expired.

## Headings and fonts

GitHub removes CSS and font settings from README markdown, so body text always uses GitHub's own font. Section headings are therefore SVG images with the Playfair Display font embedded (a dark and a light file each) in `assets/headings/`. To change a heading or the font, edit `HEADINGS` or `FAMILY` in `tools/make_headings.py` and run:

```bash
python tools/make_headings.py
```

The generated cards use the system serif stack (Times New Roman, Times, Liberation Serif) so they render without any download.

## Cards

The Principles, Selected Work and Latest Public Projects sections are SVG cards, because GitHub removes CSS from README markdown. Each SVG embeds two fonts (Playfair Display for titles, Source Serif 4 for text) and wraps its text with measured glyph widths.

- **Principles and Selected Work:** edit the text in `.github/cards-content.json`, then run `python tools/make_cards.py`. It rewrites `assets/cards/` and the blocks between the `CARDS` markers in `README.md`.
- **Latest Public Projects:** generated by `profile-card.yml` from your public repositories into `assets/projects/`. A repository gets a **Live demo** label when its GitHub *Website* field is set, and tags from its language and Topics.
- **Fonts:** `python tools/fetch_fonts.py` downloads them again and re-measures the glyph widths (needs Edge or Chrome).

## Responsive layout

GitHub cannot run CSS media queries in a README, so the layout adapts with two rules (checked by `tests/test_responsive.py`):

1. Images get a fixed pixel width. GitHub shrinks an image to the screen width, so cards sit side by side on a desktop and stack on a phone.
2. No fixed heights (they would squash the image on a narrow screen), no small percentage widths and no multi-column tables.

Card widths are 420px, 270px (contact) and 168px (stats). The profile summary card is generated by an external service at a fixed 700px, so its text is small on a phone.

## Hero

The profile hero is a card (`assets/hero/hero-card.svg`) next to the banner. Edit the text under `hero` in `.github/cards-content.json`, then run:

```bash
python tools/make_hero.py            # rebuild the card and the README block
python tools/make_hero.py --avatar   # also rebuild the avatar from assets/image/SR (2).jpg
```

The card (440px) and banner (340px) are fixed-width images in one centred paragraph, so they sit side by side on a wide screen and stack on a narrow one. The tagline rotates with an SVG animation and stays static for visitors who prefer reduced motion. `assets/banner-3d.svg` only had its viewBox cropped (its artwork is unchanged) so it matches the card height.

## Undo

Every card audit change is a separate commit and the old version is tagged. See [UNDO.md](UNDO.md).

## Latest Public Projects

The section between the `RECENT_PROJECTS` markers in `README.md` is rewritten by `profile-card.yml` from your public, non-fork repositories. Edit text outside the markers freely; text inside them is overwritten.

## Tests

The SVG builders have unit tests in `tests/`. Run them with:

```bash
pip install requests
python -m unittest discover -s tests -v
```

The `Tests` workflow runs the same command on every push and pull request.

To run the tests and the badge check together before committing, use `python tools/check.py`.

## Badges

Static tech and section badges are self-hosted in `assets/badges/` so they keep working when shields.io is rate limited. `assets/badges/manifest.json` maps each file to its shields.io source URL.

```bash
python tools/sync_badges.py            # download badges that are missing
python tools/sync_badges.py --refresh  # re-download every badge
python tools/sync_badges.py --check    # verify the files exist and are SVGs
```

Only the followers and stars badges stay remote, because they show live numbers.
